# Web クライアントの方針

## 目的
- 再生機能から作る。一覧と再生の画面を先に作り、管理機能（読みの修正、手動マージ、M3U など）は後からその画面の中に足す。管理画面を先に作ると、操作の置き場が散らばるため。

## 技術選定
- Nuxt 4 を SPA（SSR なし）で使う。静的に書き出してサーバーのバイナリに埋め込み、Node.js なしで配信するため。
- TypeScript、pnpm、Tailwind CSS 4、shadcn-vue（shadcn-nuxt）、`lucide-vue-next` を使う。shadcn-vue の部品はリポジトリに生成されるので、見た目をデザインに合わせて直せるため。
- テストは Vitest と Playwright、検査は `@nuxt/eslint` と `vue-tsc`。
- Node.js は 22 を使う。

## デザイン
- ユーザーが Claude Design で作った「Suisei design system」の色づかい、文字、部品の見た目に合わせる。画面構成や表示項目はそのとおりにせず、サーバーが持たないデータ（タグ、ストレージ、レーベルなど）は出さない。
- 色、余白、角丸、影は Design の CSS 変数をそのまま写し、Tailwind の `@theme` から使う。ダークを基準に、`data-theme="light"` でライトに切り替える。
- テーマは OS の設定に従い、設定の画面から手動でも選べる。手動の選択はブラウザの `localStorage` に残す。
- 書体は Geist のラテンとラテン拡張の字形だけを同梱し、外部の CDN から読まない。ほかの字形と日本語は OS の書体に任せる。Noto Sans JP やほかの字形を同梱すると、バイナリに埋め込む量が増えるため。
- アイコンは Lucide、ロゴは四芒星の SVG をアクセント色で塗る。
- アプリのアイコン（ブラウザのタブ、ホーム画面）は四芒星の画像を使う。元の画像を切り出さずにそのまま縮める。サイドバーなどのロゴは SVG のままにする。小さく出すと画像の細部がつぶれ、ライトテーマでも色を合わせられるため。
- 画面の文言は日本語で直接書き、多言語の仕組みは入れない。

## 画面構成
- 操作感は Spotify や Apple Music に寄せ、ライブラリの入れ子は既存の Subsonic クライアントに合わせる。
- 最初からスマホに対応する。スマホは下に「ホーム」「検索」「ライブラリ」「プレイリスト」「設定」のタブを置き、表示中のタブをもう一度押すとそのタブの最初の画面に戻る。
- ライブラリはアルバム、アーティスト、トラック、ジャンル、お気に入りの一覧を出し、項目を押すとその一覧に移る。
- PC は同じ五つを左のサイドバーに並べ、ライブラリの項目は最初から展開して出す。画面が広いので、一手減らすため。
- PC は内容を角丸の大きなパネル一枚に収め、中の一覧は枠や角丸を持たない行を区切り線で並べる。箱を入れ子にすると野暮ったく見えるため、デザイン案と同じく箱は一段にする。スマホはパネルを画面いっぱいに広げる。
- 画面の上端に、画面の名前を出す見出しの帯を置き、スクロールしても残す。今どの画面にいるかを常に分かるようにするため。下の階層の画面では、帯の左に戻る矢印（押せる範囲 44px 四方）を置く。PC ではサイドバーから移れるので、ライブラリの一覧の矢印はスマホだけに出す。
- 詳細の画面は大きな見出しを内容の側に持ち、それがスクロールで隠れたら帯に名前を出す。
- 詳細の画面の戻る矢印は、アプリの中で前にいた画面に戻る（ブラウザの「戻る」と同じ）。同じ詳細にはアーティストや作曲家など複数の画面から入るので、戻り先を決め打ちにしない。直にリンクで開いて前の画面がないときは、その種類の一覧に移る。
- 内容の幅は、画面の幅が 1200px 未満なら 640px まで、1200px 以上なら 1040px まで、1920px 以上なら 1440px までにする。広い画面で横いっぱいに広げると一覧の行を目で追いにくいため上限は残し、広い画面では表の形の一覧や情報欄を並べられるように広げる。上限はどの画面も同じにし、画面を移ってもタイトルや左端が動かないようにする。
- PC で内容を中央に置くか左に寄せるかは、開発モードのときに設定の画面の「開発」で選べるようにする。実機で見比べて決めるための一時的な項目で、決まったら外す。既定は中央で、選択はブラウザの `localStorage` に残す。
- 再生バーは、スマホではタブの上、PC では画面の下端に置く。画面を移っても再生を途切れさせないため、再生の状態はページの外に持つ。
- 画面の幅が 1440px 以上なら、下端の再生バーの代わりに右の欄（1440〜1679px は 320px、1680〜1919px は 380px、1920px 以上は 400px）に再生プレイヤーを置く。広い画面ではジャケットや次に再生する曲まで見せられるため。

## 一覧
- Subsonic API（`/rest`）を JSON で呼び、認証は Cookie のセッションに任せる。エラー 40 が返ればセッションが切れたとみなし、ログインの画面に移す。
- データは Nuxt の `useAsyncData` と `$fetch` で取り、取得のライブラリは入れない。依存を増やさないため。
- 件数の多い一覧は 100 件ずつ読み足し、`@tanstack/vue-virtual` で画面に見える行だけを描く。数千件でも DOM が膨らまないようにするため。スクロールするのはレイアウトのパネルなので、スクロール要素を指定できるこのライブラリを使う。
- 一覧の読み込み済みの項目とスクロール位置は、一覧ごと（引数を含む鍵で）`useState` に持つ。ブラウザの「戻る」で一覧に戻ったときだけ、取り直さずに位置を戻す。リンクやタブで開いたときは先頭から読む。残すのは開いているタブの中だけで、再読み込みで捨てる。
- アルバムの一覧は `getAlbumList2` で 100 枚ずつ読み足し、ジャケットのグリッドとリストを切り替えられる。グリッドの列の数は内容の幅に合わせて 2〜8 列にし、広い画面でジャケットが大きくなりすぎないようにする。リストの行はジャケット（56px）、アルバム名、アーティストと年、曲数を並べる。ジャケットは曲の行（40px）より大きくする。アルバムはジャケットで見分けることが多いため。
- アルバムの並び順は名前順（既定）、新着順、アーティスト順、年順から選べる。年順は新しい年から並べ、年のないアルバムは出さない（`byYear` が年の範囲で絞るため）。選んだ表示と並び順はブラウザの `localStorage` に残す。
- アーティストの一覧は、サーバーが読みの行（ア、カ、A など）ごとに分けた見出しで区切って並べ、見出しは見出しの帯の下に残す。スクロールしても今どの行にいるかが分かるようにするため。アーティストの画像はないので、名前の頭文字を丸に入れて出す。
- アーティストの一覧では、アルバムアーティストと、曲のアーティスト全員を切り替えられる。既定はアルバムアーティスト。一覧から詳細に移って戻ると、選んでいた方に戻る。
- トラックの一覧は全曲を `search3`（空の検索語）で 100 曲ずつ読み足し、ジャケット、曲名、アーティストとアルバム名、長さを一行に並べる。並び順は曲名順、アルバム順、アーティスト順から選べ、既定は曲名順。並べ替えはサーバーの `search3` の独自の引数 `songSort` に任せる。全曲を読まずに並べ替えるため。選んだ順はブラウザの `localStorage` に残す。
- ジャンルの一覧は `getGenres` で全件を一度に取り、背の低い色のタイル（狭い画面で 2 列、広い画面で 3 列）にジャンル名と曲数、アルバム数を載せる。ジャンルは名前だけでは見分けにくいので、色で目印を付けるため。色は名前順に並べたときの位置で順に割り当てる。名前から計算すると似た色が並びやすいため。並び順を変えても色は変えない。並び順は名前順と曲の多い順から選べ、全件が手元にあるので Web で並べ替える。名前順は読みの順にする。選んだ順はブラウザの `localStorage` に残す。
- ジャンルの詳細は、そのジャンルの曲を `getSongsByGenre` で 100 曲ずつ読み足して並べる。ジャンルで探すときは曲を聴きたいことが多いため。並び順はトラックの一覧と同じく曲名順、アルバム順、アーティスト順から選べ、`songSort` でサーバーに任せる。URL はジャンル名を入れた `/library/genres/<ジャンル名>`。
- アルバムの一覧とアーティストの一覧（作曲家の一覧を含む）には「お気に入り」の切り替えを置き、お気に入りだけに絞り込める。アルバムはサーバーの `getAlbumList2` の独自の引数 `starred` で読み直し、選んだ並び順のまま絞り込む。お気に入りにした日の順では並べない。アーティストは読み込んだ一覧を Web で絞り込み、読みの行の見出しは残す。切り替えは「戻る」で戻ったときは保ち、開き直すとオフに戻す。
- お気に入りの画面は、お気に入りにした曲を `getStarred2` で取って並べる。お気に入りは曲で使うことが多いため。アルバムとアーティストのお気に入りは、それぞれの一覧で絞り込む。並び順は新しい順（既定）、古い順、タイトル順、アーティスト順、アルバム順から選べる。タイトル順、アーティスト順、アルバム順は `songSort` でサーバーに任せ、読みの順にする。古い順は新しい順を Web で逆にする。選んだ順はブラウザの `localStorage` に残す。
- 作曲家の一覧はライブラリの項目として別に置き、作曲、作詞、編曲のどれかで関わった人をまとめて並べる。作詞と編曲のタグが付いた曲は少なく、別の項目にするほどの数がないため。
- アルバムの詳細は、ジャケットをぼかして暗くした背景を見出しの後ろに敷き、手前にジャケット、アルバム名、アーティスト、年とジャンルと曲数と長さを並べる。どのアルバムを開いているかを一目で分かるようにするため。見出しの帯は、スクロールするまで背景を透かす。アーティスト名はアーティストの詳細（アルバムの表示）へのリンクにする。
- アルバムの詳細では、アルバムと曲をハートでお気に入りにできる。押したらすぐに見た目を切り替え、サーバーが失敗を返したら元に戻す。「…」のメニューは、中身ができるまで開発モードのときだけ出す。
- 曲の一覧（トラック、ジャンルの詳細、お気に入り、アーティストの詳細）の行にも、長さの左にハートを置く。
- 付け外しした結果は、ページを読み直すまで曲とアルバムの ID ごとに一か所で覚え、どの画面のハートもそれを先に見る。曲の一覧は見えている行だけを描き、読み込んだ一覧を画面を移っても残すので、読み込んだときの状態だけを見ると、スクロールや画面の行き来で付け外しが元に戻って見えるため。
- お気に入りの画面でハートを外しても、行はその場に残す。押し間違えたときにすぐ付け直せるようにするため。外した曲は、次に一覧を読み直したときに消える。
- アーティストの詳細は、どの一覧から開いたかで出すものを変える。同じ人でも、アルバムアーティストとして見たいときと、曲の歌い手や作曲者として見たいときで、探すものが違うため。開いた一覧はリンクの `?view=` で渡し、再読み込みや共有した URL でも同じ表示にする。
  - アルバムアーティストの一覧から（`albums`）：アルバムアーティストになっているアルバムだけをグリッドで並べる。
  - アーティストの一覧から（`tracks`）：アルバムアーティストになっているアルバムを上に横スクロールで並べ、その下に曲のアーティストとして参加した曲をアルバムごとの見出しで区切って並べる。
  - 作曲家の一覧から（`composer`）：作曲、作詞、編曲で関わった曲を、アルバムで区切らずに並べる。
  - 曲はサーバーの `getArtist` の独自の引数 `songs` で一度に取る。
  - 並び順は、アーティストの名前の下で選べる。選択はスクロールしても見出しの帯のすぐ下に、背景の帯ごと残す。曲の多い一覧の途中でも並べ替えられるようにするため。アルバムの表示とアーティストの表示は新しい順、古い順、アルバム名順、作曲家の表示は新しい順、古い順、曲名順で、既定は新しい順。最近の作品を先に見せるため。アーティストの表示では、横スクロールのアルバムと曲の見出しを同じ順に並べる。
  - 並べ替えは Web でする。`getArtist` のアルバムの順は他のクライアントにも返るので、サーバーの順は変えない。
  - 選んだ並び順は表示ごとにブラウザの `localStorage` に残す。開くたびに選び直さずに済むようにするため。
- ジャケットは表示の 2 倍の大きさでサーバーに頼む。高密度の画面でもぼやけないようにするため。

## 検索
- 検索の画面は、見出しの帯に入力欄を置き、`search3` でアーティスト、アルバム、曲をまとめて探す。
- 打ち終えて 300ms 止まったら検索し、検索語を URL の `?q=` に入れる。履歴は積まずに置き換える。詳細から「戻る」で結果に戻れ、再読み込みや共有した URL でも同じ結果になるようにするため。検索のタブを押し直すと検索語を消す。
- 結果は区切りの見出しの下に、アーティスト 5 人、アルバム 10 枚（横スクロール）、曲 10 曲を並べる。一画面で種類ごとの当たりを見渡せるようにするため。収まらない種類には「すべて見る」を置き、`/search/<種類>?q=` でその種類だけを 100 件ずつ読み足す。続きがあるかを知るため、出す件数より 1 件多く頼む。
- 結果の並びはサーバーの `search3` に従う（読みの順）。
- アーティストの結果は、曲のアーティストの表示（`?view=tracks`）で開く。検索には曲にだけ参加している人も出るため。
- 曲の行を押すと、ほかの曲の一覧と同じく、押した曲から結果の曲を順にキューに入れる。
- 最近の検索語は残さない。入力が空なら、何で探せるかの案内だけを出す。

## プレイリスト
- 一覧は `getPlaylists` で取り、行（ジャケット 56px、名前、曲数と長さ）で並べる。名前で探すことが多く、ジャケットは最初の曲のアルバムのものなので、ジャケットだけでは見分けにくいため。
- 新しいプレイリストは「新規プレイリスト」で見出しの帯の下に名前の欄を出して作り、作ったら詳細に移る。
- 詳細はアルバムの詳細に寄せ、ジャケットをぼかした背景、名前、曲数と長さ、「すべて再生」を並べる。曲の行はトラックの一覧と同じ形にする。曲のアルバムがばらばらなので、トラック番号の行にはしない。
- 「編集」で名前と曲の並びを変えられる。曲はキューと同じく、右端の取っ手で並べ替え、PC は × のボタン、スマホは左に払って外す。普段は行を押すと再生するので、押し間違えて消さないように編集の間だけこの操作を出す。
- 編集は手元の写しを変え、「完了」でまとめて保存する。「キャンセル」なら捨てる。保存に失敗したら、編集を続けたまま知らせる。曲の並びが変わったら、`updatePlaylist` で元の曲をすべて外して新しい並びで入れ直す。曲の ID が多いと URL に収まらないので、引数はフォームで送る（`formPost`）。
- プレイリストの削除は編集の中に置き、もう一度確かめてから消す。
- 曲をプレイリストに足す操作は、曲とアルバムの「…」のメニューから行う。

## 再生
- layout に `<audio>` を一つだけ置き、キュー、再生中の曲、再生位置を `useState` に持つ。画面を移っても再生を途切れさせないため。
- 曲の行を押すと、押した曲から始め、その一覧の曲を順にキューに入れる。読み足す一覧では、読み込み済みの曲だけが入る。アルバムの「すべて再生」は一曲目から始める。
- 曲が終われば次の曲に進み、キューの最後の曲が終わればその曲を出したまま止める。
- 前の曲は、3 秒より先まで進んでいれば曲の頭に戻し、そうでなければ前の曲に移る。多くのプレイヤーと同じ動きにするため。
- 再生中の曲は、曲の一覧で曲名をアクセント色にする。
- 右の欄、引き出す再生画面、PC の下端の再生バーでは、進み具合のバーをつまんで動かし、好きな位置に移れる（シーク）。動かしている間は表示だけを変え、離したときに移る。スマホの小さな再生バーは表示だけにする。指で押しにくく、引き出す再生画面で足りるため。
- 音量は PC の右の欄と下端の再生バーで変えられ、選んだ音量はブラウザの `localStorage` に残す。スマホでは置かない。iPhone のブラウザはページから音量を変えられず、本体のボタンで足りるため。
- シャッフルをオンにすると、再生中の曲を先頭に残して残りの曲を混ぜる。オフにすると元の並びに戻し、再生中の曲の位置から続ける。新しく再生を始めたときもシャッフルのままにする。
- リピートは押すたびに「なし」「キュー全体」「1 曲」を切り替える。キュー全体なら最後の曲の後に先頭へ戻り、1 曲なら同じ曲を繰り返す。シャッフルとリピートは、ページを読み直すと消えるキューに合わせて残さない。
- スマホでは、再生バーを押すと再生画面を下から引き出す。上端は少し空けて後ろの画面を暗く透かし、今の画面に重ねて開いたことが分かるようにする。中身は右の欄の再生プレイヤーと同じものにする。小さな再生バーには操作を置く場所がなく、画面ごとに作り分けると操作がずれるため。パネルのどこでも下に引く、後ろの画面を押す、下向きの矢印、Esc、画面の移動で閉じる。取っ手だけを引かせると、閉じる操作が狙いにくいため。中身がスクロールしていれば先にスクロールし、シークのバーなど指で動かす部品の上で始めた操作では閉じない。
- スマホの再生画面は、再生中の曲のジャケットをぼかして暗くした背景を敷き、曲が変わったら重ねて入れ替える。何を鳴らしているかを一目で分かるようにし、アルバムの詳細と見た目をそろえるため。暗くする層は画面全体に濃く（上 70%、下 85%）かける。曲名、キュー、操作の段の文字はぼかしたジャケットの上に直接乗るので、明るいジャケットでも薄い文字が読めるようにするため。右の欄は内容のパネルと並ぶので、背景を敷かずに落ち着かせる。
- 再生のボタンと再生プレイヤーのジャケットは、再生中は強く、止めているときは弱く光らせる。光の強さで鳴っているかどうかが分かるようにするため。再生プレイヤーのジャケットには枠線を付けない。
- 音声は `stream` で元のファイルのまま受け取る。音質を落とさず、Range でシークできるため。
- 元のファイルを鳴らせなければ、`format=mp3` で変換させて読み直す。MP3 はどのブラウザでも鳴り、サーバーは 320kbps で書き出す。ブラウザが鳴らせる形式を先に判定しないのは、ALAC と AAC がどちらも `audio/mp4` で見分けられず、ブラウザごとの癖にも従えるため。変換して鳴った形式（`contentType` と `suffix` の組）はページを読み直すまで覚え、同じ形式の曲は最初から変換する。ただし `audio/mp4` は覚えない。ALAC で覚えると、鳴らせる AAC まで変換してしまうため。変換しても鳴らせなければ、鳴らせなかったことを再生バーに出す。
- 変換した音声は途中から読めないので、変換して鳴らしている曲のシークは、`timeOffset` でその位置から変換し直させる。再生位置は、頭出しした位置に `<audio>` で進んだ長さを足して数える。
- キューは、再生プレイヤーと再生バーのキューのボタンで開く。再生プレイヤーでは、ボタンを下端の段の右に置く。表示を切り替えるボタン（後で足す歌詞など）を同じ段に並べ、どちらの表示でも同じ位置で押せるようにするため。スマホの再生画面と右の欄では、ジャケットと曲名の場所をキューに入れ替え、下のシークのバーと操作の段はそのまま残す。Apple Music に寄せ、キューを見ながらでも同じ場所で操作できるようにするため。キューを出している間は、操作の段の間隔と下の余白を詰めて下に寄せ、キューを大きく見せる。下端の再生バーの PC は、右端に内容へ重ねて出す。
- キューは再生中の曲を上に固定し、その下に「再生履歴」と「次に再生」を並べる。再生中の曲は背景を敷かず、ジャケットと曲名を大きくしてアルバム名も添える。ジャケットをぼかした背景の上では、箱や帯で囲むと浮いて見えるため。開いたときは「次に再生」まで送って再生履歴を隠し、下にスクロールすると再生履歴が出る。次に何が鳴るかを先に見せつつ、済んだ曲にも押して戻れるようにするため。見出しは小さく薄くし、スクロールしても一覧の上端に残す。見出しには背景を敷かず、一覧の上端を見出しの高さぶん透かして、そこに今いる区切りの見出しを重ねる。背景を敷くと、ジャケットをぼかした背景の上で帯が浮いて見えるため。
- キューの行を押すとその曲に移る。次に再生する曲は、行の右端の取っ手を引いて並べ替えられる。取っ手でだけ引かせるのは、行を押す操作や、再生画面を引いて閉じる操作と取り合わないようにするため。並べ替えは SortableJS に任せ、マウスと指で同じ動きにするため HTML の drag and drop は使わない。
- キューから曲を消すのは、PC はマウスを乗せると出る × のボタン、スマホは行を左に払う操作にする。再生中の曲は消さない。鳴っている曲を消すと次に何を鳴らすかが曖昧になるため。
- スマホの再生画面は、キューを出していても、下の操作の段を引けば閉じる。キューの上では、再生履歴が上に残っている間はスクロールを先にして閉じない。閉じたら、次に開いたときはジャケットの表示から始める。
- シャッフル中に並べ替えても、シャッフルをオフにするとシャッフル前の並びに戻る。消した曲はシャッフル前の並びからも消す。
- 曲の半分か 4 分の早い方まで聴いたら、`scrobble` で再生回数に数える。Last.fm と同じ基準にし、ほかのクライアントと数え方をそろえるため。数えるのは実際に聴いた長さで、シークで飛ばした分は入れない。頭から鳴らし始めるたびに一度だけ送り、1 曲のリピートや前の曲のボタンで頭に戻したときも数え直す。再生を始めたときの `submission=false`（再生中の表示）は送らない。送るのに失敗しても再送しない。
- 再生中の曲の曲名、アーティスト、アルバム、ジャケットを Media Session API で OS のロック画面や通知に出し、そこから再生、一時停止、前後の曲、シークを受ける。10 秒の戻しと送りは受けない。iPhone では前後の曲と同時に出せないため。キューの端で移れないときは、その方向のボタンを出さない。
- ログアウトなどで layout が外れたら、キューを捨てる。

## ログイン
- 起動時に `GET /api/me` を呼び、401 ならログイン画面に移す。ログインの後は元の画面に戻す。
- パスワードはブラウザに保存しない。認証はサーバーが発行する Cookie のセッションに任せる（docs/server.md の「Web クライアントのログイン」）。

## 開発
- 開発サーバーは `/api` と `/rest` を `SUISEI_DEV_BACKEND`（既定は `http://127.0.0.1:4533`）に中継する。
- 使えない UI（未実装の選択肢など）は、開発モードのときだけ押せない状態で出し、それ以外では出さない。先に置き場所を実機で確かめつつ、本番では未完成のものを見せないため。開発モードは、サーバーの `GET /api/me` が `dev: true` を返すときと、Nuxt の開発サーバーで動かすとき。
- 設定の画面の「開発」の項目も、開発モードのときだけ出す。
- E2E テストは `/api` と `/rest` の応答を偽物に差し替える。Web の CI に Rust のビルドを持ち込まないため。サーバーとの結合は Sprite の実機で確かめる。
