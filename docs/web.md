# Web クライアントの方針

## 目的
- 再生機能から作る。一覧と再生の画面を先に作り、管理機能（読みの修正、手動マージ、M3U など）は後からその画面の中に足す。管理画面を先に作ると、操作の置き場が散らばるため。

## 技術選定
- Nuxt 4 を SPA（SSR なし）で使う。静的に書き出してサーバーのバイナリに埋め込み、Node.js なしで配信するため。
- TypeScript、pnpm、Tailwind CSS 4、shadcn-vue（shadcn-nuxt）、`lucide-vue-next` を使う。shadcn-vue の部品はリポジトリに生成されるので、見た目をデザインに合わせて直せるため。
- テストは Vitest と Playwright、検査は `@nuxt/eslint` と `vue-tsc`。
- Node.js は 22 を使う。

## デザイン
- ユーザーが Claude Design で作った「Suisei design system」の色づかい、文字、部品の見た目に合わせる。画面構成や表示項目はそのとおりにせず、サーバーが持たないデータ（タグ、ストレージ、レーベルなど）は出さない。
- 色、余白、角丸、影は Design の CSS 変数をそのまま写し、Tailwind の `@theme` から使う。ダークを基準に、`data-theme="light"` でライトに切り替える。
- テーマは OS の設定に従い、設定の画面から手動でも選べる。手動の選択はブラウザの `localStorage` に残す。
- 書体は Geist のラテンとラテン拡張の字形だけを同梱し、外部の CDN から読まない。ほかの字形と日本語は OS の書体に任せる。Noto Sans JP やほかの字形を同梱すると、バイナリに埋め込む量が増えるため。
- アイコンは Lucide、ロゴは四芒星の SVG をアクセント色で塗る。
- アプリのアイコン（ブラウザのタブ、ホーム画面）は四芒星の画像を使う。元の画像を切り出さずにそのまま縮める。サイドバーなどのロゴは SVG のままにする。小さく出すと画像の細部がつぶれ、ライトテーマでも色を合わせられるため。
- 画面の文言は日本語で直接書き、多言語の仕組みは入れない。

## 画面構成
- 操作感は Spotify や Apple Music に寄せ、ライブラリの入れ子は既存の Subsonic クライアントに合わせる。
- 最初からスマホに対応する。スマホは下に「ホーム」「検索」「ライブラリ」「プレイリスト」「設定」のタブを置き、表示中のタブをもう一度押すとそのタブの最初の画面に戻る。
- ライブラリはアルバム、アーティスト、トラック、ジャンル、お気に入りの一覧を出し、項目を押すとその一覧に移る。
- PC は同じ五つを左のサイドバーに並べ、ライブラリの項目は最初から展開して出す。画面が広いので、一手減らすため。
- PC は内容を角丸の大きなパネル一枚に収め、中の一覧は枠や角丸を持たない行を区切り線で並べる。箱を入れ子にすると野暮ったく見えるため、デザイン案と同じく箱は一段にする。スマホはパネルを画面いっぱいに広げる。
- 画面の上端に、画面の名前を出す見出しの帯を置き、スクロールしても残す。今どの画面にいるかを常に分かるようにするため。下の階層の画面では、帯の左に戻る矢印（押せる範囲 44px 四方）を置く。PC ではサイドバーから移れるので、ライブラリの一覧の矢印はスマホだけに出す。
- 詳細の画面は大きな見出しを内容の側に持ち、それがスクロールで隠れたら帯に名前を出す。
- 詳細の画面の戻る矢印は、アプリの中で前にいた画面に戻る（ブラウザの「戻る」と同じ）。同じ詳細にはアーティストや作曲家など複数の画面から入るので、戻り先を決め打ちにしない。直にリンクで開いて前の画面がないときは、その種類の一覧に移る。
- 内容の幅は、画面の幅が 1200px 未満なら 640px まで、1200px 以上なら 1040px までにする。広い画面で横いっぱいに広げると一覧の行を目で追いにくいため上限は残し、広い画面では表の形の一覧や情報欄を並べられるように広げる。
- PC で内容を中央に置くか左に寄せるかは、開発モードのときに設定の画面の「開発」で選べるようにする。実機で見比べて決めるための一時的な項目で、決まったら外す。既定は中央で、選択はブラウザの `localStorage` に残す。
- 再生バーは、スマホではタブの上、PC では画面の下端に置く。画面を移っても再生を途切れさせないため、再生の状態はページの外に持つ。
- 画面の幅が 1440px 以上なら、下端の再生バーの代わりに右の欄（1440〜1679px は 320px、1680px 以上は 380px）に再生プレイヤーを置く。広い画面ではジャケットや次に再生する曲まで見せられるため。再生を作るまでは、何も再生していない状態だけを出す。

## 一覧
- Subsonic API（`/rest`）を JSON で呼び、認証は Cookie のセッションに任せる。エラー 40 が返ればセッションが切れたとみなし、ログインの画面に移す。
- データは Nuxt の `useAsyncData` と `$fetch` で取り、取得のライブラリは入れない。依存を増やさないため。
- 件数の多い一覧は 100 件ずつ読み足し、`@tanstack/vue-virtual` で画面に見える行だけを描く。数千件でも DOM が膨らまないようにするため。スクロールするのはレイアウトのパネルなので、スクロール要素を指定できるこのライブラリを使う。
- 一覧の読み込み済みの項目とスクロール位置は、一覧ごと（引数を含む鍵で）`useState` に持つ。ブラウザの「戻る」で一覧に戻ったときだけ、取り直さずに位置を戻す。リンクやタブで開いたときは先頭から読む。残すのは開いているタブの中だけで、再読み込みで捨てる。
- アルバムの一覧は、ジャケットのグリッドで名前順に並べる。列の数は内容の幅に合わせて 2〜6 列にし、広い画面でジャケットが大きくなりすぎないようにする。グリッドとリストの切り替えと並び順の選択は、開発モードのときだけ出す（未実装の選択肢があるため）。
- アーティストの一覧は、サーバーが読みの行（ア、カ、A など）ごとに分けた見出しで区切って並べ、見出しは見出しの帯の下に残す。スクロールしても今どの行にいるかが分かるようにするため。アーティストの画像はないので、名前の頭文字を丸に入れて出す。
- アーティストの一覧では、アルバムアーティストと、曲のアーティスト全員を切り替えられる。既定はアルバムアーティスト。一覧から詳細に移って戻ると、選んでいた方に戻る。
- トラックの一覧は全曲を `search3`（空の検索語）で 100 曲ずつ読み足し、ジャケット、曲名、アーティストとアルバム名、長さを一行に並べる。並び順は曲名順、アルバム順、アーティスト順から選べ、既定は曲名順。並べ替えはサーバーの `search3` の独自の引数 `songSort` に任せる。全曲を読まずに並べ替えるため。選んだ順はブラウザの `localStorage` に残す。
- ジャンルの一覧は `getGenres` で全件を一度に取り、背の低い色のタイル（狭い画面で 2 列、広い画面で 3 列）にジャンル名と曲数、アルバム数を載せる。ジャンルは名前だけでは見分けにくいので、色で目印を付けるため。色は名前順に並べたときの位置で順に割り当てる。名前から計算すると似た色が並びやすいため。並び順を変えても色は変えない。並び順は名前順と曲の多い順から選べ、全件が手元にあるので Web で並べ替える。名前順は読みの順にする。選んだ順はブラウザの `localStorage` に残す。
- ジャンルの詳細は、そのジャンルの曲を `getSongsByGenre` で 100 曲ずつ読み足して並べる。ジャンルで探すときは曲を聴きたいことが多いため。並び順はトラックの一覧と同じく曲名順、アルバム順、アーティスト順から選べ、`songSort` でサーバーに任せる。URL はジャンル名を入れた `/library/genres/<ジャンル名>`。
- アルバムの一覧とアーティストの一覧（作曲家の一覧を含む）には「お気に入り」の切り替えを置き、お気に入りだけに絞り込める。アルバムは `getAlbumList2` の `starred` で読み直すので、絞り込んでいる間はお気に入りにした新しい順になる。アーティストは読み込んだ一覧を Web で絞り込み、読みの行の見出しは残す。切り替えは「戻る」で戻ったときは保ち、開き直すとオフに戻す。
- お気に入りの画面は、お気に入りにした曲を `getStarred2` で取って並べる。お気に入りは曲で使うことが多いため。アルバムとアーティストのお気に入りは、それぞれの一覧で絞り込む。並び順は新しい順（既定）、古い順、タイトル順、アーティスト順、アルバム順から選べる。タイトル順、アーティスト順、アルバム順は `songSort` でサーバーに任せ、読みの順にする。古い順は新しい順を Web で逆にする。選んだ順はブラウザの `localStorage` に残す。
- 作曲家の一覧はライブラリの項目として別に置き、作曲、作詞、編曲のどれかで関わった人をまとめて並べる。作詞と編曲のタグが付いた曲は少なく、別の項目にするほどの数がないため。
- アーティストの詳細は、どの一覧から開いたかで出すものを変える。同じ人でも、アルバムアーティストとして見たいときと、曲の歌い手や作曲者として見たいときで、探すものが違うため。開いた一覧はリンクの `?view=` で渡し、再読み込みや共有した URL でも同じ表示にする。
  - アルバムアーティストの一覧から（`albums`）：アルバムアーティストになっているアルバムだけをグリッドで並べる。
  - アーティストの一覧から（`tracks`）：アルバムアーティストになっているアルバムを上に横スクロールで並べ、その下に曲のアーティストとして参加した曲をアルバムごとの見出しで区切って並べる。
  - 作曲家の一覧から（`composer`）：作曲、作詞、編曲で関わった曲を、アルバムで区切らずに並べる。
  - 曲はサーバーの `getArtist` の独自の引数 `songs` で一度に取る。
  - 並び順は、アーティストの名前の下で選べる。選択はスクロールしても見出しの帯のすぐ下に、背景の帯ごと残す。曲の多い一覧の途中でも並べ替えられるようにするため。アルバムの表示とアーティストの表示は新しい順、古い順、アルバム名順、作曲家の表示は新しい順、古い順、曲名順で、既定は新しい順。最近の作品を先に見せるため。アーティストの表示では、横スクロールのアルバムと曲の見出しを同じ順に並べる。
  - 並べ替えは Web でする。`getArtist` のアルバムの順は他のクライアントにも返るので、サーバーの順は変えない。
  - 選んだ並び順は表示ごとにブラウザの `localStorage` に残す。開くたびに選び直さずに済むようにするため。
- ジャケットは表示の 2 倍の大きさでサーバーに頼む。高密度の画面でもぼやけないようにするため。

## ログイン
- 起動時に `GET /api/me` を呼び、401 ならログイン画面に移す。ログインの後は元の画面に戻す。
- パスワードはブラウザに保存しない。認証はサーバーが発行する Cookie のセッションに任せる（docs/server.md の「Web クライアントのログイン」）。

## 開発
- 開発サーバーは `/api` と `/rest` を `SUISEI_DEV_BACKEND`（既定は `http://127.0.0.1:4533`）に中継する。
- 使えない UI（未実装の選択肢など）は、開発モードのときだけ押せない状態で出し、それ以外では出さない。先に置き場所を実機で確かめつつ、本番では未完成のものを見せないため。開発モードは、サーバーの `GET /api/me` が `dev: true` を返すときと、Nuxt の開発サーバーで動かすとき。
- 設定の画面の「開発」の項目も、開発モードのときだけ出す。
- E2E テストは `/api` と `/rest` の応答を偽物に差し替える。Web の CI に Rust のビルドを持ち込まないため。サーバーとの結合は Sprite の実機で確かめる。
